## 1. 天禧比赛规则对定位的硬约束（决定"能不能赢热度值"）

| 维度 | 官方规则要点 | 对定位的启示 |
|---|---|---|
| **评选公式** | 综合分 = 体验等级 + 场景满足度 + **热度值**（使用量 + 添加量） | 定位必须**拉得动下载/添加**，而非小众专业 |
| **热度值机制** | 同一 Lenovo ID 对同一 Skill 每自然日最多计 1 次有效添加；防刷严格 | 靠"广受众 + 易上手 + 强触发词"拉**不同人**的添加，而非刷量 |
| **重点鼓励方向** | 学生群体 / **生产力工具** / **自动执行类 Agent** / 本地文件联动 / 专业领域 / 多模态 | "办公室提效"精准命中"生产力工具"；"挑出最该自动化的任务"命中"自动执行" |
| **SKILL.md 要求** | "写清楚解决的问题/场景/使用方式/输出/确认环节/风险边界 → 平台识别准、用户上手快、审核顺" | 缺 quickstart（已知 G4 缺口）会直接拖累体验等级与热度值 |
| **合规** | 须原创/合法授权；**去 WorkBuddy 品牌、不含专属定价** | 比赛版必须去品牌（已在方案 doc 规划） |

**结论**：比赛要的是"普通人愿意装、装了能用、用得顺"的办公生产力 Skill。"办公室提效"比"消费洞察"更贴这条赛道。

### 关键发现：两份白空间
1. **个人办公 AI 节省的"衡量层"是空的**——执行类 Skill 满天飞，但没有任何一个帮职场人"看见自己省了多少、该自动化什么"。这是我们的**未占领位置**。
2. **"消费洞察/成本分析"话术已被开发者工具占用**（LangSmith 等），且紧挨 `agent-analytics-report` 的领地。

## 4. 定位分析：为什么"消费洞察"是陷阱

把定位改成 **「Token 消费洞察 + 提效助手」** 会同时踩三个雷：

1. **撞车姐妹项目**：`agent-analytics-report` 的本质就是"用量/成本/消费分析"。把"消费洞察"写进名字，**恰恰抹掉了你想保留的差异**——用户会问"这和那个 Agent 用量报告有什么区别？"
2. **收窄受众**："消费/洞察"是 FinOps/开发者语境；"办公室提效"是 every-office-worker 语境。比赛热度值要的是**广添加**，不是窄而深。
3. **偏离比赛鼓励方向**：天禧鼓励"生产力工具/自动执行"，"消费洞察"更像后台分析报表，不在聚光灯下。

**正确姿势**：保留「办公室 / 提效」作为品类锚点，把"Token 账本 + 提效洞察"当作**差异化机制**（HOW），而不是品类名（WHAT）。

```
推荐定位陈述：
For [用 AI 做办公任务的职场人] who [想知道自己到底省了多少、该把什么交给自动化],
[办公室 Token 提效助手] is an [AI 提效账本与洞察工具] that
[把你"笨办法 vs 用 AI"的耗时/Token 记下来，算出节省、画出趋势、挑出最该自动化的任务].
Unlike [会议纪要/PPT 这类"替你做"的执行型 Skill], [我们只衡量与优化你的 AI 投入产出，不重造轮子].
```

### 命名建议（比赛展示名）
- 主推：**「办公室 AI 提效助手」**（最广受众；Token 作为内部指标不进名字）
- 副标/描述锚点：**「用 Token 账本量化你的 AI 提效」**
- 如需保留辨识度：**「办公室 Token 提效助手」**（维持现名亦可，仅需在描述里补"衡量/洞察"语义）

## 5. 决策建议（直接回答你的问题）

**结论：采用融合方案 C ——「办公室 Token 洞察与提效助手」(slug 建议 `office-token-insight`)。既不取纯 A(改为"Token 消费洞察+提效助手")，也不取纯 B(维持原样)。**

> 本结论与今日早些时候的另一份深度分析(`office-token-booster-定位与竞品分析.md`)完全一致，本节的联网调研独立佐证了它的前提：天禧"办公室"是场景加分锚、执行类 Skill 极度拥挤、成本分析工具全为 B2B/开发者向。

**为什么是 C，而不是你提出的两个选项：**
- ❌ **不选 A（"Token 消费洞察 + 提效助手"）**：会同时踩两个雷——(1) "消费/用量洞察" 紧挨姐妹项目 `agent-analytics-report`（本质是 Agent 用量/成本分析），**边界模糊、外界分不清两个 Skill**，正好撞你最想避免的"太像"；(2) 丢掉"办公室"场景词 → 天禧终评场景加分掉；且"消费洞察"是 FinOps/开发者语境，**收窄受众**。
- ⚠️ **不选 B（维持"办公室 Token 提效助手"）**：方向对，但名字里的"提效助手"暗示"替你高效干活"，而代码实测只记账+统计+可视化、**不执行**任何办公任务（G1 缺口）→ 用户预期落差会直接拉低天禧"体验等级"与"热度值"。
- ✅ **选 C（"办公室 Token 洞察与提效助手"）**：三者兼顾——
  1. **保「办公室」** → 拿天禧终评场景加分，且与 `agent-analytics-report` 形成「**消费端个人办公 vs 系统端多 Agent 分析**」的天然区隔（你担心的相似度反而被讲清楚了）；
  2. **加「洞察」** → 诚实表达"看清省了多少、不替你干活"，预期管理到位 → 体验分稳、口碑好 → 热度值更可持续；
  3. **留「提效」** → 承接 2026 Token 效率元年热点（微软限 Token / FinOps 火爆），"省了多少 Token/时间"是强钩子，利于搜索曝光与下载。

**一句话定位陈述（直接进 SKILL.md）：**
> For 用 AI 做办公任务的职场人 who 想知道自己到底省了多少、该把什么交给自动化，[办公室 Token 洞察与提效助手] is 一个 AI 提效账本与洞察工具 that 把你"笨办法 vs 用 AI"的耗时/Token 记下来，算出节省、画出趋势、挑出最该自动化的任务。Unlike 会议纪要/PPT 这类"替你做"的执行型 Skill，我们只衡量与优化你的 AI 投入产出。

### v0.9 / 比赛提交必须同步做的（否则定位落不了地）
- 修 **G4 缺 quickstart**：SKILL.md 给"复制即跑的示例账本 + 3 条自然语言触发示例"，直接抬升体验等级与热度值。
- SKILL.md `description` 埋**强触发词**：会议纪要、周报、Excel、PPT、文档整理、AI 提效、省 token、办公效率可视化——匹配用户搜索与平台识别。
- 诚实写边界："本 Skill 衡量与洞察你的 AI 办公提效，不替代会议纪要/PPT 等执行型工具"——既避 G1 失实，又自然与执行类 Skill 形成互补叙事。
- 比赛版去 WorkBuddy 品牌（方案 doc 已规划）。

---

## 6. 一句结论
> 别丢「办公室」这个词（它是天禧场景加分锚，也是和 `agent-analytics-report` 划清"消费端 vs 系统端"的刀刃）；也别裸奔成"提效助手"（暗示执行会伤体验分）。**「办公室 Token 洞察与提效助手」** 让办公室保场景、洞察管预期、提效蹭热点——三者兼得，且和姐妹项目天然区隔。
